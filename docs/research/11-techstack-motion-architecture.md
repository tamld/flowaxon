# WS2 – Tech Stack & Motion Architecture Decision (FlowAxon v4)

## 1. Current rendering architecture inventory
- HTML: static `index.html` generated by `scripts/inject-v3-ui.mjs`. Injects UI into base template.
- CSS: compiled `assets/css/flowaxon.css`. No inline styles.
- JS: compiled `assets/js/flowaxon.js`. No inline scripts.
- 3D/SVG: static SVG rigs generated by `scripts/build-anatomy-rigs.mjs`.
- Build steps:
  1. Node runs `inject-v3-ui.mjs` → writes `index.html`.
  2. Node runs `build-anatomy-rigs.mjs` → writes SVG/JS assets.
  3. Go builds binary (`main.go`) that serves `dist/` with caching headers.
- Dependencies: Node built‑ins only (fs, path, etc.). No external npm packages (knowledge).
- If `index.html` regenerated from scratch:
  - Injection scripts fail → UI missing.
  - CSP checks may break if inline scripts added.
  - Go binary unchanged.

**Zero‑new‑runtime‑dependency motion?**  
- Achievable with CSS `animation-timeline` + WAAPI for transforms & opacity.  
- Lost: complex sequencing, precise timing control, coordinated multi‑element choreography, Lottie JSON animations, 3‑D transforms, interactive triggers beyond hover/focus, advanced easing curves not expressible in CSS.

## 4. Recommendation
- Primary: static HTML + Node build scripts + vanilla JS (status‑quo) with CSS `animation-timeline` + WAAPI motion layer.
- Rationale: meets CSP/SRI, fits RSS budget, zero runtime overhead, deterministic builds, maintainer‑friendly.
- Second choice: Astro static output with islands for incremental interactivity.
- Migration risks:
  1. **Script injection breakage** – regenerate `index.html` with updated `inject-v3-ui.mjs`; CI gate verifies script hash.
  2. **Motion feature loss** – ensure motion design can be expressed via CSS/WAAPI; prototype in sandbox before commit.
  3. **Asset SRI mismatch** – existing `verify-sri.sh` fails on rebuilt assets; run script in CI to re‑sign.
